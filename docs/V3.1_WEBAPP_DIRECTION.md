# v3.1 Windows App Direction

v3.0.0 remains the immutable production baseline.

v3.1 replaces the technical three-column native manager as the primary experience with a guided web-first Windows application.

## Chosen production shell

- The existing Go background agent remains the source of truth for job discovery, scoring, storage, application preparation, and local API operations.
- The primary UI is HTML/CSS/JavaScript and remains reusable independently of the shell.
- The v3.1 production Windows shell will use Wails v2 with the Microsoft Evergreen WebView2 Runtime, creating a genuine desktop application window rather than opening Microsoft Edge as a browser app.
- Build the Windows application with the WebView2 bootstrapper embedded so a missing Evergreen Runtime can be handled without making Edge browser installation a prerequisite.
- The old Win32 manager remains available only as a repair/fallback path while v3.1 is stabilized.
- `127.0.0.1:8787` remains loopback-only for agent health/debug/API compatibility; the normal user does not need to know or type this address.

## Simplified user experience

Primary navigation: Home, Jobs, Profile & CV, Settings.

First-run flow:

1. **Ready** - Haya's CV/profile is already present and the app can analyze a vacancy URL immediately.
2. **Job discovery (optional)** - connect Yahoo using a Yahoo app password only if automatic Yahoo job-alert discovery is wanted.
3. **Application answers (optional)** - add verified work authorization, sponsorship, start-date, and salary answers only when known. Blank values do not block the app.
4. **Choose automation** - Monitor Only, Prepare & Ask (recommended), or Strict Auto Apply.

The Home screen should always show one plain-language next action, not technical service state. Advanced diagnostics, logs, local folders, and repair controls live under Settings > Advanced.

## Safety and privacy

- Never request or store Haya's normal Yahoo password.
- Yahoo app-password storage uses Windows DPAPI.
- Unknown legal/application answers are never invented.
- Strict Auto Apply must stop for unknown required answers, CAPTCHA/account verification, assessments/video questions, unsupported application routes, or unverified recipient addresses.
- v3.0.0 remains untouched while v3.1 is preflighted on its development branch.
