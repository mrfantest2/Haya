# v3.1 Preflight / Stabilization Gate

v3.0.0 remains the immutable production baseline. v3.1 must not replace it until every release gate below is green.

## Architecture

- Native Go background agent remains the source of truth.
- No Docker, WSL, Node.js, administrator/UAC setup, or external cloud dashboard at runtime.
- Primary UI is an embedded Wails v2 / Microsoft Evergreen WebView2 Windows window using the web-first frontend.
- The shipped Windows candidate remains a single EXE; the WebView2 bootstrapper strategy is embedded for the rare case where the Evergreen Runtime is missing.
- Native Win32 manager remains available only through `--native-manager` as a repair fallback during stabilization.
- The loopback HTTP agent remains available for health/debug compatibility, but the normal user never needs to open a browser or type a port.

## Required functional gates

1. Windows x64 build, `go vet`, unit tests and JavaScript syntax validation pass.
2. Agent starts exactly once and `/healthz` + `/api/status` respond; duplicate launches are ignored and logged.
3. Fresh install is usable without Yahoo credentials.
4. Manual vacancy URL workflow functions without Yahoo credentials.
5. Yahoo app password is optional and stored only through Windows DPAPI when supplied.
6. Work authorization, sponsorship, start date and salary are optional verified answers; blank values never block app startup.
7. Strict Auto Apply still requires a usable mail credential and verified corporate application email route before sending.
8. CV is present after first install and replacement accepts PDF only.
9. Job canonicalization/fingerprint dedupe tests pass.
10. Config, job database, application directory and logs survive repair/upgrade.
11. Default launcher installs into the user profile, starts the agent and opens one embedded WebView2 app window; a second launch focuses the existing window instead of creating duplicates.
12. Desktop shortcut creation is best-effort and must never block installation.
13. Uninstall supports optional history backup and removes per-user autostart.
14. No modal popup loops during install, start, scan or config changes.
15. UI works at desktop, maximized and narrow/mobile-like widths.
16. Agent log records clean start/stop events and duplicate-start suppression so unexplained restarts can be diagnosed.
17. WebView2-missing preflight exercises the embedded bootstrapper/friendly recovery path without popup loops.

## Live-account gates before Strict Auto Apply is recommended

- Yahoo app-password IMAP connection test passes on Haya's Windows account.
- At least one genuine alert is parsed and deduplicated correctly.
- At least one real vacancy is scored and prepared correctly.
- One controlled application package is reviewed by Haya.
- Automatic sending remains off until the corporate email safety gate is verified on a real vacancy.

## Release rule

Only publish v3.1.x after GitHub Windows CI is green and the exact candidate passes a real Windows user preflight. v3.0.0 remains downloadable and unchanged.
